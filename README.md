# Pakko Telegram Bot

Pakko - Telegram-бот для поиска и анализа информации в стиле Perplexity. Бот работает в личных сообщениях и группах, использует OpenAI Responses API, умеет подключать hosted web search, хранит краткий контекст чата в SQLite и автоматически сжимает историю.

## Возможности

- ответы на русском и английском языках;
- работа в личных чатах, группах и супергруппах;
- в группах бот отвечает только на `@username`, `Pakko` или `Пакко`;
- команды `/start`, `/help`, `/clear`, `/status` с практичными подсказками и человекочитаемым статусом памяти;
- контекст отдельно для каждого чата;
- очистка контекста через `/clear`, явную просьбу или молча после 10 минут неактивности;
- суммаризация длинной истории для снижения расхода токенов;
- опциональный веб-поиск через OpenAI hosted `web_search` с коротким статусом проверки источников;
- структурированные ответы с фактами, предположениями, выводами и источниками;
- логирование времени ответа, использования поиска, токенов и примерной стоимости;
- понятный ответ на вложения и нетекстовые сообщения: бот просит продублировать вопрос текстом.

## Архитектура

```text
pakko/
  config.py           # Pydantic settings из .env
  logging.py          # стандартное логирование
  main.py             # точка входа
  assistant/          # бизнес-оркестрация ответа
  llm/                # OpenAI Responses API
  memory/             # SQLite-репозиторий и контекст чата
  search/             # правило search-first для веб-поиска
  summarization/      # сжатие истории
  telegram/           # aiogram handlers и групповые триггеры
```

## Локальный запуск

1. Установите Python 3.12+.
2. Создайте и активируйте виртуальное окружение.
3. Установите проект:

```bash
pip install -e ".[dev]"
```

4. Создайте `.env` из примера:

```bash
cp .env.example .env
```

5. Заполните `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и `OPENAI_API_KEY`.
6. Запустите бота:

```bash
python -m pakko.main
```

## Docker

```bash
cp .env.example .env
docker compose up --build
```

SQLite-файл хранится в `./data`.

## Конфигурация

Основные переменные:

- `OPENAI_MODEL` - модель без изменения кода. По умолчанию `gpt-5.4-mini`, так как в документации OpenAI она описана как более дешевый и быстрый mini-вариант для рабочих задач.
- `OPENAI_REASONING_EFFORT` - `none`, `low`, `medium`, `high` или `xhigh`. По умолчанию `medium`.
- `OPENAI_TIMEOUT_SECONDS` - таймаут одного запроса к OpenAI. По умолчанию `90` секунд.
- `OPENAI_REQUEST_RETRIES` - количество повторов для временных OpenAI-сбоев: сетевые ошибки, timeout, rate limit и 5xx. По умолчанию `3`.
- `MAX_ANSWER_SECONDS` - мягкий бюджет на дополнительные попытки повысить уверенность ответа, например повтор с веб-поиском. Первичный ответ не обрывается по этому таймеру. По умолчанию `45` секунд.
- `ENABLE_WEB_SEARCH` - включает hosted web search.
- `WEB_SEARCH_CONTEXT_SIZE` - размер поискового контекста: `low`, `medium`, `high`. По умолчанию `medium`.
- `CONTEXT_TTL_SECONDS` - время неактивности, после которого контекст чата очищается.
- `SUMMARIZE_AFTER_MESSAGES` - порог сообщений для суммаризации. По умолчанию `24`.
- `MAX_RECENT_MESSAGES` - сколько последних сообщений оставлять после суммаризации. По умолчанию `12`.
- `OPENAI_INPUT_PRICE_USD_PER_MILLION` и `OPENAI_OUTPUT_PRICE_USD_PER_MILLION` - цены для примерного логирования стоимости. Проверяйте их перед production-запуском.

## Поведение в группах

Бот игнорирует обычные сообщения в группах. Он отвечает только если текст содержит:

- `@pakkkobot` или другой username из `TELEGRAM_BOT_USERNAME`;
- `Pakko`;
- `Пакко`.

Сравнение регистронезависимое. Адресация удаляется перед отправкой запроса в LLM.

## Веб-поиск

Pakko работает в режиме search-first: если `ENABLE_WEB_SEARCH=true`, каждый непустой пользовательский запрос сразу отправляется в OpenAI Responses API с hosted `web_search`. Это нужно, чтобы бот сначала проверял свежую информацию в интернете, а затем дополнял ответ знаниями модели и рассуждением.

Каждый сырой ответ LLM содержит технический маркер уверенности, который удаляется перед отправкой пользователю. Повторная попытка с веб-поиском остаётся как защитный механизм для сценариев, где первичный ответ был получен без поиска и маркер показывает низкую уверенность или необходимость веб-проверки. В обычном режиме search-first повтор не нужен, потому что поиск уже используется в первом ответе.

Если первичный запрос с hosted `web_search` падает из-за временного сбоя, Pakko повторяет запрос без веб-поиска с отдельной инструкцией: дать лучший доступный ответ, честно обозначить ограничения и не заменять ответ техническим fallback-сообщением.

Если веб-поиск нужно отключить для экономии, отладки или работы без hosted search, установите `ENABLE_WEB_SEARCH=false`. В этом режиме бот отвечает без первичной интернет-проверки и честно отражает ограничения уверенности через внутренний маркер.
